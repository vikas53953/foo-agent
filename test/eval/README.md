# AI eval adapter

This lane adds a DeepEval adapter beside the promptfoo suite proposed in [PR #97](https://github.com/vikas53953/foo-agent/pull/97). The adapter uses DeepEval `LLMTestCase`, `BaseMetric`, and `evaluate()` with a local deterministic metric: every fixture carries an input, a pretend application reply, required/forbidden output terms, and an AT id. The TypeScript suite executes foo's real job runner, tool gate, vault handlers, prompt builder, page gate, and CLI probe, so a passing case is evidence about an application boundary rather than a standalone refusal function.

Run the deterministic suite with:

```text
corepack.cmd pnpm exec vitest --config test/eval/vitest.config.ts run --maxWorkers=2
```

Run the second framework adapter after installing its scoped dependency (the install is under `test/eval/.deps` and does not touch the shared runtime):

```text
python -m pip install --target test/eval/.deps -r test/eval/requirements.txt
mkdir test/eval/results
corepack.cmd pnpm exec tsx test/eval/production-cases.ts > test/eval/results/production-cases.json
$env:PYTHONPATH=(Resolve-Path test/eval/.deps); python test/eval/deepeval_adapter.py
```

The adapter executes 21 DeepEval cases, including five outputs generated by foo's production prompt builder and page gates (email, paste, file, web, and AI page), plus five current-main Claude result envelopes and one expected failing model-output fixture (`AT-119`) to prove the metric detects an invalid completion. The live receipts are evaluated by parsing `<act>` and requiring `decision.kind: reply`; forbidden action kinds fail the case, so attack words quoted in the reply do not create false failures. It reported 20/21 positive outputs and one expected negative, with zero provider calls and `$0` evaluator cost. The five live probes report a separate `$0.04956` list-price subtotal.

The deterministic suite and DeepEval evaluator do not call Claude or install a remote judge. Separately, root authorized bounded Claude CLI probes through the private launcher; the retained direct probes and five current-main production-boundary receipts contain no enabled tools or unsafe action decisions. The key was injected only into those child processes and was not read or stored in this lane. These are model-output and prompt/command boundary probes; a full real-AI application journey remains pending. The existing browser-level injection article remains the control: [ART-injection.test.ts](https://github.com/vikas53953/foo-agent/blob/main/test/articles/ART-injection.test.ts).
