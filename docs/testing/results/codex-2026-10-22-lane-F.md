The Lane F mutation choice was compared against primary project documentation before adding configuration: [Stryker JS](https://stryker-mutator.io/docs/stryker-js/introduction/) matches this TypeScript app and the existing PR #101 workflow; [PITest](https://pitest.org/) targets JVM bytecode; [Mutode](https://github.com/sa1nt/Mutode) is another JavaScript option but would introduce a second mutation workflow. Stryker was installed only under `scripts/audit` and the bounded run used the existing shared test runtime without changing shared dependencies.

For static/dependency review, [Knip](https://knip.dev/), [depcheck](https://github.com/depcheck/depcheck), and [npm-check](https://github.com/dylang/npm-check) were compared. The owned scanner uses the existing runtime and reports candidates without adding dependencies; these tools were not installed or run. For network capture, [Playwright routing](https://playwright.dev/docs/network), [mitmproxy](https://docs.mitmproxy.org/stable/), and Electron's [`net`](https://www.electronjs.org/docs/latest/api/net) were compared. The production boundary fixture was selected because it exercises the app's redaction choke point without credentials or external traffic; a real capture remains blocked.
