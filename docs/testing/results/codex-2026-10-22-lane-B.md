## Framework choice

| Option                      | Primary evidence                                                                                                               | Fit for this lane                                                                                                                           |

| cucumber-js                 | [official repository](https://github.com/cucumber/cucumber-js), [installation guide](https://cucumber.io/docs/installation/)   | A sound Node BDD runner, but it would require a separate browser lifecycle and reporting bridge for the existing Playwright Electron tests. |

The scoped package in `test/bdd/package.json` links to the repository's existing Playwright modules. This avoids a second Playwright instance while keeping dependency and lockfile changes inside the owned subtree. `playwright.config.ts` generates native tests from `features/**/*.feature`, uses the existing `test/e2e/launch.ts`, and emits an ignored JSON result file.

## Launcher modes

Pretend mode writes an isolated fake-AI JSONL script and calls [`test/e2e/launch.ts`](../../../test/e2e/launch.ts) with isolated data, local, and output directories. It seeds only through the existing `FOO_TEST` bridge and uses real renderer controls and assertions for each scenario.

Real mode is explicit with `FOO_BDD_AI_MODE=real`, `FOO_BDD_REAL_AI_PROVIDER`, and `FOO_BDD_REAL_AI_HOME`. Missing or invalid values fail with a `BDD real-AI mode is blocked` error. With an existing isolated `claude-cli` or `codex-cli` profile, the fixture writes only provider selection to an isolated settings file, preserves the installed CLI discovery path, sets `HOME`/`USERPROFILE` to that profile, and starts the real engine through the same Electron launcher with `FOO_TEST=0`. It never reads or creates credentials.
