## (a) What changes for the user

1. **Kit pieces in replies.** When a picture helps, foo's reply holds one or more live pieces drawn by foo in foo's look
   (light, dark, high contrast, Animations Off/Basic). The 13 pieces Vikas picked are: line chart (also area and bar),
   map with stops, + / − and sliders, compare side by side, timeline, week calendar, tabs, timed checklist, quick
   calculator, goal ring, pick from a list, pick a time, short form. Tabs is a standard A2UI part; the catalog (§(c)) adds
   12 foo components plus `LiveStamp`, so "13 pieces" and "13 foo components" are different lists. Pieces appear while
   the reply streams.
2. **AI-made pages in a sealed box.** When no piece fits, or the user asks ("make me a tool"), the AI writes a small page.
   It runs in a sealed frame with no network, no files and no access to accounts, keys or money. Any action it asks for
   goes through foo's normal gates. A kit piece or a one-line status shows first while the page is built.
3. **"foo read:" line** under the user's message: the people, places, dates, times and amounts foo understood.
4. **Ask about this:** select words in a foo reply, then ask a side question about them without stopping the job running.
5. **Big paste becomes a file:** a paste over 10,000 characters becomes a saved text file (pick 7).
6. **Visuals setting:** Mostly words / Balanced (default) / Show me visuals. Mostly words means no kit pieces and no AI pages
   unless the user asks for one.
7. **Say-this vs do-this chips** after a reply: reply chips (grey, ↩, fill the composer, never send, as P1's follow-ups)
   and action chips (accent, icon: call, open map, add to calendar, open link). Action chips that act for the user go
   through the normal gates.
8. **Live stamp + Keep:** a piece built from live data shows "Data as of {time}" with Refresh. "Keep" saves a piece or AI page
   so it can be found again (pick 9).

## (f) Picks where the ask forks (each logged in docs/decisions/R1.tsv)

1. **Trace label:** the plan milestone R1 ships beside; if Vikas has not set the order when T1 starts, the next `M<n>`
   still open on the plan at that time. T1 does not wait.
2. **Catalog source of truth** is zod schemas in `src/shared/kit/`, which generate the AI prompt section and validate every
   message (json-render and OpenUI follow the same idea; no library needed for it).
3. **Renderer:** foo's own React components on top of the A2UI message model. Google's `@a2ui/react` is not used (its
   styling bug and foo's tokens; libraries.md).
4. **Map without a basemap in v1.** A web basemap would send tile requests that the app CSP blocks (FE-22) and that tell a
   tile server where the user's stops are. Offline map tiles downloaded once with a permission row (06-2 §6.4) can come
   in a later CR.
5. **Calculator** uses a small hand-written expression evaluator, no `eval`, no `Function`.
6. **Side question** is a normal message with the existing `reply_to_id` and the new `messages.side` flag. The engine
   answers it from context and does not cancel or re-plan the running job.
7. **Big paste:** above 10,000 characters (ChatGPT's threshold, docs) the paste is saved as `pasted-{time}.txt` in the
   chat's files; 2,001–10,000 stays the existing "Pasted text" chip.
8. **Visuals default** is Balanced. Mostly words still renders tables (04 §13.2) because they are text.
9. **Keep:** a kept item is a `kept_items` row shown in the chat's Files tab. Kit surfaces are stored as their A2UI JSON
   plus a PNG snapshot. AI pages are stored as a `.foopage` blob plus a PNG; "Open" always reopens a kept page in the
   sealed box, never with `shell.openPath`. "Show in folder" is allowed. No plain `.html` file is ever written.
10. **Charts library:** none. The pieces are SVG drawn by foo (02 §F19 rules), so no chart or map dependency is added.
11. **Streaming inside a fence** (implementation note on 08-4 §25.5 item 2, found in T2): inside a `a2ui or `page
    fence a bare line break ends a "sentence" for the release gate, so each A2UI line is released on its own (AT-353).
    Prose outside fences keeps the §25.5 rule unchanged.
12. **Kit and page fences draw only in foo's own text** (04 §13.5): a helper's, a system line's or the user's fence stays
    a code block, and `kit:action` accepts only a surface hosted by a foo message.
13. **Pages need a user tap to act** (T5 review): the host answers `requestAction` and `openLink` only while the user's
    tap is live (`navigator.userActivation.isActive`), else `refused: 'declined'`; one C-26 dialog at a time, its URL
    fixed when it opens. A page cannot send messages or open links by itself (Article 6).
14. **Fenced text skips the word filter** (implementation note on 08-4 §25.5, found in T5): inside any fence (```page,

```a2ui and plain code, which 04 §13.1 shows verbatim) the release gate keeps the Redactor step but does not map,
rewrite or drop Article 2 words, so page scripts and A2UI keys stay valid. Prose outside fences is unchanged.
15. **`ai_page` card payload** is `{ html: string }` (≤ 512 KB); a kept page is served from its `.foopage` blob through
the same `pages.serve()` path.
```
